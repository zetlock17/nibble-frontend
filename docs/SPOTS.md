# Споты на карте

Фронтенд загружает места из `GET /api/spots?city_id=1`. Существующий прокси Vite и Nginx направляет запросы на `http://149.154.68.183/api/`. Другая локальная БД сама по себе не меняет этот серверный набор. Чтобы работать со своим бэкендом, настройте прокси в `vite.config.ts` и `nginx/default.conf` или задайте `VITE_API_BASE_URL` и разрешите CORS на бэкенде. Перезапустите Vite после изменения конфигурации.

При выборе карточки или метки карта переходит к координатам места. Описание, виды рыб и способы ловли загружаются отдельно через `GET /api/spots/{id}`. Идентификаторы берутся из БД; демонстрационный справочник рыб не используется. Список API содержит только название, район, координаты и фото, поэтому описание и виды доступны в подробностях. Изображения показываются только при наличии `photo_url`.

`cityId` компонента `PlacesMap` по умолчанию равен `1` — Владивосток на текущем сервере. Выбор города в хедере пока не подключён. Фильтр видов остаётся отключённым; фильтр «Откуда ловить» отключён, поскольку API не передаёт признак ловли с берега или лодки. Способ ловли вроде донной снасти не заменяет этот признак.

## Добавление через Swagger

Откройте [Swagger сервера](http://149.154.68.183/api/docs#/spots). В разделе `spots` есть только `GET /spots` и `GET /spots/{spot_id}`. Создать или изменить место через Swagger сейчас нельзя. Для этого потребуется добавить защищённый `POST /spots` на бэкенде. В рамках подключения фронтенда бэкенд не менялся.

## Добавление напрямую в БД

Выполняйте команды на машине с БД того бэкенда, к которому подключён фронтенд. Запуск в локальном `nibble_back` меняет локальную БД, а не БД удалённого сервера.

Из каталога `nibble_back` откройте PostgreSQL:

```sh
make see-db
```

Проверьте доступные города:

```sql
SELECT id, name FROM cities ORDER BY id;
```

Вставьте следующий блок в открытый `psql`. Он запросит значения и создаст один спот. Название и координаты должны относиться к проверенному месту. `lat` — широта от −90 до 90, `lon` — долгота от −180 до 180. Дробную часть вводите через точку. Во Владивостоке широта около 43, долгота около 132; на карту они передаются в порядке `[lon, lat]`.

```sql
\prompt 'ID города: ' spot_city
\prompt 'Название места: ' spot_name
\prompt 'Широта (lat): ' spot_lat
\prompt 'Долгота (lon): ' spot_lon
\prompt 'Район (можно оставить пустым): ' spot_area
\prompt 'Описание (можно оставить пустым): ' spot_description

INSERT INTO spots (city_id, name, lat, lon, area, description, is_active)
VALUES (
  :'spot_city'::bigint,
  :'spot_name',
  :'spot_lat'::numeric,
  :'spot_lon'::numeric,
  NULLIF(:'spot_area', ''),
  NULLIF(:'spot_description', ''),
  true
)
RETURNING id, name, lat, lon;
```

Сохраните возвращённый `id`. При стандартном режиме `psql` запись сохраняется сразу. Фото необязательно; для него поле `photo_url` должно содержать доступный браузеру URL реального снимка места.

Чтобы указать виды рыб и способы ловли, сначала найдите их идентификаторы:

```sql
SELECT id, name FROM species ORDER BY name;
SELECT id, name FROM fishing_methods ORDER BY name;
```

Для каждой связи выполните нужный блок. `moderator` обозначает сведения, внесённые модератором; другие допустимые источники — `open_sources` и `reports`. Само наличие рыбы в месте не означает свежий улов.

```sql
\prompt 'ID спота: ' spot_id
\prompt 'ID вида рыбы: ' species_id
INSERT INTO spot_species (spot_id, species_id, data_source)
VALUES (:'spot_id'::bigint, :'species_id'::bigint, 'moderator')
ON CONFLICT DO NOTHING;

\prompt 'ID способа ловли: ' method_id
INSERT INTO spot_methods (spot_id, method_id)
VALUES (:'spot_id'::bigint, :'method_id'::bigint)
ON CONFLICT DO NOTHING;
```

В Swagger вызовите `GET /spots` с `city_id` нужного города и проверьте запись. Затем нажмите «Обновить места» на фронтенде. Для отображения меток нужен настроенный браузерный ключ Яндекс Карт; список работает и без ключа. Перезапуск бэкенда и новая миграция для добавления записи не нужны.
