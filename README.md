# Клёв

Веб-сервис для рыбаков Владивостока и окрестностей: карта мест по видам рыб, лента уловов, погода, справочник и подборки снастей с переходом на Фарпост.

Начата визуальная вёрстка на React + TypeScript + Vite. Готовы хедер, боковая навигация, погодная карточка, лента и профиль на моках. В ленте работают фильтры по источнику, месту и виду рыбы, сброс, локальные лайки и подписки. Поиск, выбор города, публикация улова, комментарии и редактирование профиля ещё не подключены к продуктовой логике.

Профиль открывается из бокового меню и по кнопке пользователя в хедере. Показывает обложку, инициалы, имя, город, описание, количество постов и подписчиков. Ниже используются общие карточки `PostCard`, без подписки на себя. Вкладок «Уловы / Коллекция» и счётчика подписок нет. Данные находятся в `src/mocks/profile`, фотография переиспользуется из демонстрационной ленты. Кнопки публикации и редактирования отключены до подключения соответствующих форм.

Справа от постов на широком экране расположен блок «Фото с рыбалок», занимающий оставшуюся ширину. Сетка содержит восемь снимков и меняется от двух до четырёх колонок по ширине блока. На узком экране он находится над лентой. Общий компонент `PhotoGrid` открывает снимок в новой вкладке и обрабатывает пустой альбом и ошибку изображения. Альбом пока использует отдельные иллюстративные моки `src/mocks/profile/photos.ts`, а не фото из постов. Источники: [src/assets/images/profile/SOURCES.md](src/assets/images/profile/SOURCES.md).

Приложение занимает высоту окна, прокрутка документа заблокирована. Хедер расположен вне прокручиваемых областей. На компьютере левая колонка и фильтры ленты неподвижны. В справочнике рыб и каталоге снастей заголовок уходит вверх при прокрутке, а панель фильтров закрепляется у верхнего края области контента. Карточки продолжают прокручиваться под фильтрами. Высокая левая панель прокручивается отдельно. В профиле прокручивается область справа, галерея закрепляется у её верхнего края. Прокрутка за пределами вложенных списков отключена через `overscroll-behavior: none`, внешние контейнеры используют `overflow: clip`. На телефоне содержимое под хедером прокручивается целиком. Измерения хедера через JavaScript не используются.

Демонстрационные карточки показывают пользователей сервиса и Telegram, записи с фото и без фото, с необязательными сведениями об улове. Реальный парсинг Telegram пока не подключён. У вымышленной публикации «Источник» отображается без ссылки. Компонент принимает HTTPS-ссылку на `t.me` при подключении оригинальных публикаций. Лайки и подписки сбрасываются после перезагрузки страницы.

```text
src/
  assets/brand/       Логотип сервиса
  assets/fonts/       Manrope и лицензия
  assets/icons/
    actions/         Действия: поиск, добавление, удаление

    weather/         Солнце, облака, ветер, осадки

    map/             Метки, слои, глубины
    social/          Реакции, комментарии, соцсети
  assets/images/     Иллюстративные фотографии для моков
  components/layout/header/ Хедер
  components/layout/sidebar/ Погода и боковая навигация
  features/weather/  Карточка погоды, типы и изображения состояний
  components/ui/     Кнопки, поля, аватары, метки, выбор и переключатель
  features/feed/     Лента, фильтры, карточка поста и типы
  features/map/      Компоненты и логика карты
  features/fish/     Компоненты и логика справочника
  features/tackle/   Каталог объявлений, карточки, фильтрация и типы
  mocks/
    profile/         Демонстрационный профиль и его публикации
    feed/            Демонстрационные публикации
    weather/         Демонстрационный прогноз
    header/          Демонстрационные данные хедера
    fish/            Рыбы, описания и периоды ловли из макета
    tackle/          Примеры объявлений Фарпоста
  pages/home/        Главная страница
  pages/profile/     Страница профиля
  styles/
    globals.css      Подключение Tailwind и базовые стили
    tokens.css       Переменные темы
```

Импорты из `src` используют алиас `@/`, например `@/components/ui/button/Button`. Внутренние модули добавляются по мере разработки.

## Документация

Раздел «Снасти и удочки» работает на семи демонстрационных объявлениях. Доступны категории, поиск по названию или продавцу, цена от/до, сортировка по дате и цене, сброс фильтров. На широком экране пять карточек в ряд. Заголовок уходит вверх при прокрутке, а блок фильтров закрепляется у верхнего края области контента. У карточек есть исходные фотографии и ссылки на конкретные объявления; продавец показывается только при наличии имени. Источники: [src/assets/images/tackle/SOURCES.md](src/assets/images/tackle/SOURCES.md). `TackleCatalog` получает `TackleState` через props: `loading`, `error` или `ready` со списком, признаком демонстрации и необязательной датой обновления. Для подключения парсера потребуется проверить его ответ и передать реальные данные в этот формат; API и автоматическое обновление пока не реализованы.

Раздел «Справочник рыб» открывается из бокового меню. Поиск по названию, сезон, способ ловли и место обитания работают совместно на шести моках. Сезон, способ ловли и место обитания выбираются через общий Select. На широком экране поиск и фильтры стоят в один ряд, поиск занимает свободную ширину. Сброс оформлен кнопкой с иконкой корзины. Один вид может иметь несколько признаков, неизвестные признаки не участвуют в соответствующем фильтре. Есть сброс всех фильтров. На широком экране четыре карточки в ряд. Новые признаки демонстрационные и требуют проверки по источникам. Фотографии иллюстративные, описания и периоды взяты из макета и требуют проверки перед использованием как справочных сведений. Источники фотографий перечислены в [src/assets/images/fish/SOURCES.md](src/assets/images/fish/SOURCES.md).

- [Концепция](docs/CONCEPT.md): что делаем, пользовательские сценарии, предлагаемая первая версия, связи данных и открытые решения.
- [Правила для агента](AGENTS.md): обязательные навыки, подход к коду, дизайну, текстам и проверкам. Читать в начале каждой сессии.

## Запуск

Нужны Node.js и npm, совместимые с установленной версией Vite. Зависимости зафиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

## Яндекс Карты

Раздел «Карта мест» открывается из бокового меню. Карта использует JavaScript API v3, начальный центр — Владивосток. Кнопки меняют масштаб и перемещают карту к геопозиции после разрешения браузера. Фильтр «Откуда ловить» отбирает демонстрационные карточки. Метки и фильтр по виду рыбы пока не подключены.

Создайте `.env.local` в корне проекта по образцу [.env.example](.env.example) и вставьте браузерный ключ.

```dotenv
VITE_YANDEX_MAPS_API_KEY=ваш_ключ
```

После изменения ключа перезапустите `npm run dev`. В PowerShell с запретом запуска `.ps1` используйте `npm.cmd run dev`.

В кабинете Яндекса заполните ограничение по HTTP Referer для локального адреса разработки и домена сайта. Ключ `VITE_*` доступен в браузере. `.env` и `.env.local` исключены из Git. В продовой сборке ключ передаётся как build-аргумент Docker из секрета GitHub `VITE_YANDEX_MAPS_API_KEY`. Требования к ключу описаны в [документации Яндекса](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html).

Без ключа показывается пустое поле с подсказкой. При ошибке загрузки доступна повторная попытка.

### Слой глубин

Кнопка «Слой глубин» загружает реальные зоны из `GET /api/depths?city_id=1`. По ответу `/api/cities` идентификатор `1` соответствует Владивостоку. `PlacesMap` принимает `cityId`; при его изменении прежние зоны снимаются, загружаются данные выбранного города. Выбор города в хедере пока не подключён.

GeoJSON проверяется перед отрисовкой. Каждый полигон `MultiPolygon` становится отдельным `YMapFeature`, внутренние кольца сохраняются. Непрозрачность заливки 55%, обводки нет; `zIndex` равен 100. Будущие маркеры мест нужно размещать выше 100. Цвета глубин заданы в `src/styles/tokens.css`. Легенда под картой внутри общей белой рамки показывает диапазоны из ответа в метрах, включая открытую границу `50+`, и текст `attribution`. При включении слоя рамка растёт вниз, размер и положение самой карты сохраняются. На широком экране карта и легенда занимают отдельные строки общей сетки: рыбак и подробности выбранного места справа выровнены только по строке карты. Появление легенды и ошибки геолокации не сдвигает рыбака и не растягивает подробности. На узком экране сохраняется последовательная раскладка под картой. Данные ориентировочные и предназначены для изучения участка до выезда, не для навигации на воде.

Запрос выполняется при первом включении. Проверенные ответы хранятся в памяти отдельно для каждого города и адреса API до перезагрузки страницы. При повторном включении используются те же объекты текущей карты. Отрисовка идёт порциями, кнопку можно выключить во время загрузки. Есть индикатор, пустое состояние, ошибка и повторная попытка. Сбой не заменяется моками.

По умолчанию используется `VITE_API_BASE_URL=/api`. Vite в режиме разработки и Nginx из Docker-образа проксируют `/api/` на `http://149.154.68.183/api/`. Браузер обращается к домену фронтенда, поэтому ему не нужны CORS-разрешение бэкенда и прямой HTTP-запрос со страницы HTTPS. На другом хостинге настройте такой же прокси; при смене бэкенда обновите адрес в `vite.config.ts` и `nginx/default.conf`. Если задаёте отдельный адрес через `VITE_API_BASE_URL`, он должен поддерживать HTTPS для сайта на HTTPS и разрешать CORS для домена фронтенда. Значение `VITE_*` публичное, применяется при запуске Vite или сборке.

[Swagger бэкенда](http://149.154.68.183/api/docs#/depths/get_depths_depths_get).
