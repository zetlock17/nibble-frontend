# Клёв

Веб-сервис для рыбаков Владивостока и окрестностей: карта мест по видам рыб, лента уловов, погода, справочник и подборки снастей с переходом на Фарпост.

Начата визуальная вёрстка на React + TypeScript + Vite. Готовы хедер, боковая навигация, погодная карточка, лента и вход через API. В ленте работают фильтры по источнику, месту и виду рыбы, сброс, локальные лайки и подписки. Публикация улова, комментарии и редактирование профиля ещё не подключены к продуктовой логике.

Поиск в хедере использует `GET /search?q=&city_id=&limit=5`, кодирует запрос через `URLSearchParams` и начинает поиск от двух символов. До загрузки города поле недоступно. После ввода ждёт 300 мс; при смене запроса или города, закрытии списка и уходе фокуса предыдущий запрос отменяется, запоздавшие ответы игнорируются. Места и рыбы показаны отдельными группами. Выбор места открывает карту с нужным спотом и загружает его подробности через `/spots/{id}`; выбор рыбы открывает подробности в справочнике через `/species/{id}`. Работают стрелки, Enter, Escape, закрытие по клику снаружи, загрузка, пустой результат и ошибка с повтором.

Регистрация, вход, восстановление сессии и выход подключены к `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/me`, `/auth/logout`. Регистрация получает города из `/cities`, запрашивает имя, почту и пароль от 8 символов, затем выполняет вход. Access token хранится только в памяти, refresh token — в HttpOnly-cookie бэкенда; пароли и токены не записываются в localStorage. При перезагрузке сессия восстанавливается. Токен обновляется перед истечением срока, защищённый запрос после 401 повторяется один раз. Параллельные запросы используют одно обновление сессии. Ошибки загрузки сессии и выхода показываются с возможностью повторить действие.

Профиль и форма улова доступны после входа. После авторизации открывается запрошенный раздел. Логотип возвращает на главную внутри приложения, без перезагрузки страницы и сброса состояния сессии. Имя, аватар и описание профиля приходят из `/auth/me`, название города — из `/cities`. Обложка иллюстративная. Счётчики, публикации и фото профиля пока не подключены к API; редактирование отключено. Черновик улова очищается при выходе из аккаунта.

Экран «Добавить улов» доступен из хедера и профиля, возврат учитывает точку входа. Поддерживает одно фото JPEG/PNG до 10 МБ с предпросмотром, заменой и удалением, несколько видов из справочника, место из списка с поиском или по отметке на карте, описание до 3000 символов. Полей даты выезда и снасти нет. Место и виды необязательны; нужно фото или текст. Выбор места общий для списка и карты, произвольные координаты недоступны. Места и отметки загружаются из `GET /api/spots?city_id=1` при первом открытии формы, моки не используются; при сбое API показывается ошибка с повтором. Черновик сохраняется между разделами до перезагрузки вкладки. Отправка и хранение публикаций не подключены: кнопка валидирует форму и сообщает об ограничении.

Справа от постов на широком экране расположен блок «Фото с рыбалок», занимающий оставшуюся ширину. Сетка содержит восемь снимков и меняется от двух до четырёх колонок по ширине блока. На узком экране он находится над лентой. Общий компонент `PhotoGrid` открывает снимок в новой вкладке и обрабатывает пустой альбом и ошибку изображения. В личном профиле альбом пока пуст; иллюстративные моки остаются в `src/mocks/profile/photos.ts`. Источники: [src/assets/images/profile/SOURCES.md](src/assets/images/profile/SOURCES.md).

Приложение занимает высоту окна, прокрутка документа заблокирована. Хедер расположен вне прокручиваемых областей. На компьютере левая колонка и фильтры ленты неподвижны. В справочнике рыб и каталоге снастей заголовок уходит вверх при прокрутке, а панель фильтров закрепляется у верхнего края области контента. Карточки продолжают прокручиваться под фильтрами. Высокая левая панель прокручивается отдельно. В профиле прокручивается область справа, галерея закрепляется у её верхнего края. Прокрутка за пределами вложенных списков отключена через `overscroll-behavior: none`, внешние контейнеры используют `overflow: clip`. На телефоне содержимое под хедером прокручивается целиком. Измерения хедера через JavaScript не используются.

Демонстрационные карточки показывают пользователей сервиса и Telegram, записи с фото и без фото, с необязательными сведениями об улове. Реальный парсинг Telegram пока не подключён. У вымышленной публикации «Источник» отображается без ссылки. Компонент принимает HTTPS-ссылку на `t.me` при подключении оригинальных публикаций. Лайки и подписки сбрасываются после перезагрузки страницы.

## Документация

Раздел «Снасти и удочки» загружает до 10 объявлений из БД через `GET /tackle?limit=10`. Ответ проверяется и преобразуется в карточки: числовой `id`, название, ссылка `url`, цена `price_from_rub` и фото `image_url`. Если цена отсутствует, показано «Цена не указана»; если фото отсутствует или не загружается — заглушка. Есть поиск по названию, границы цены и сортировка по цене; по умолчанию сохраняется порядок ответа API. Дата публикации неизвестна: `price_updated_at` относится к обновлению цены. Загрузка отменяется при выходе из раздела, при сбое есть повтор; пустой ответ и ошибка не подменяются моками. Категории из `/tackle/categories` пока не подключены. Прямой запрос к `/aggregator/farpost` из раздела не выполняется.

Раздел «Справочник рыб» использует `GET /species?q=&season=` для поиска и сезона и `GET /species/{id}` для подробностей. Способы ловли загружаются из `GET /fishing-methods`; фильтры способов и места обитания отключены до появления связей у видов в API. Числовые ID преобразуются в строки, пустые фото и месяцы показываются как неизвестные. Есть загрузка, пустое состояние, ошибка и повтор. Главная, сезонная подборка и выбор видов в форме улова используют данные API; моки рыб остались только для тестов. Общий адрес API задаётся через `VITE_API_BASE_URL`, по умолчанию `/api`.

## Карта

Раздел «Карта мест» открывается из бокового меню. Карта построена на Leaflet с тайлами OpenStreetMap, начальный центр — Владивосток. Ключи и регистрация не нужны. Библиотека и её стили подгружаются при первом показе карты. Кнопки меняют масштаб и перемещают карту к геопозиции после разрешения браузера: для геолокации нужен HTTPS или `localhost`. Список и метки загружаются из `GET /api/spots?city_id=1`. Выбор места перемещает карту и загружает подробности через `GET /api/spots/{id}`. Фото, описание, виды рыб и способы ловли показываются по данным БД. Фильтры по виду рыбы и способу ловли работают через `species_id` и `method_id`; фильтра «Откуда ловить» нет, API не передаёт признак ловли с берега или лодки. Есть загрузка, пустое состояние, ошибки, повторные попытки и кнопка «Обновить места». Моки мест не используются. [Как добавлять споты](docs/SPOTS.md): прямое добавление в БД и ограничения Swagger.

Публичный сервер `tile.openstreetmap.org` рассчитан на умеренную нагрузку. При росте трафика замените `tileUrl` в `src/features/map/leaflet-map.ts` на свой тайл-сервер или платного провайдера, см. [политику использования тайлов](https://operations.osmfoundation.org/policies/tiles/).

Координаты в API и данных хранятся как `[долгота, широта]`. Leaflet принимает `[широта, долгота]`, перестановка выполняется в `toLatLng` и при отрисовке глубин.

### Слой глубин

Кнопка «Слой глубин» загружает реальные зоны из `GET /api/depths?city_id=1`. По ответу `/api/cities` идентификатор `1` соответствует Владивостоку. `PlacesMap` принимает `cityId`; при его изменении прежние зоны снимаются, загружаются данные выбранного города. Выбор города в хедере пока не подключён.

GeoJSON проверяется перед отрисовкой. Каждый полигон `MultiPolygon` становится отдельным слоем Leaflet, внутренние кольца сохраняются. Непрозрачность заливки 55%, обводки нет. Зоны рисуются под метками, выбранная метка поверх остальных. Цвета глубин заданы в `src/styles/tokens.css`. Легенда под картой внутри общей белой рамки показывает диапазоны из ответа в метрах, включая открытую границу `50+`, и текст `attribution`. При включении слоя рамка растёт вниз, размер и положение самой карты сохраняются. На широком экране карта и легенда занимают отдельные строки общей сетки: рыбак и подробности выбранного места справа выровнены только по строке карты. Появление легенды и ошибки геолокации не сдвигает рыбака и не растягивает подробности. На узком экране сохраняется последовательная раскладка под картой. Данные ориентировочные и предназначены для изучения участка до выезда, не для навигации на воде.

Запрос выполняется при первом включении. Проверенные ответы хранятся в памяти отдельно для каждого города и адреса API до перезагрузки страницы. При повторном включении используются те же объекты текущей карты. Отрисовка идёт порциями, кнопку можно выключить во время загрузки. Есть индикатор, пустое состояние, ошибка и повторная попытка. Сбой не заменяется моками.

По умолчанию используется `VITE_API_BASE_URL=/api`. Vite в режиме разработки и Nginx из Docker-образа проксируют `/api/` на `http://149.154.68.183/api/`. Браузер обращается к домену фронтенда, поэтому ему не нужны CORS-разрешение бэкенда и прямой HTTP-запрос со страницы HTTPS. На другом хостинге настройте такой же прокси; при смене бэкенда обновите адрес в `vite.config.ts` и `nginx/default.conf`. Если задаёте отдельный адрес через `VITE_API_BASE_URL`, он должен поддерживать HTTPS для сайта на HTTPS и разрешать CORS для домена фронтенда. Значение `VITE_*` публичное, применяется при запуске Vite или сборке.

Для авторизации Vite и Nginx меняют путь refresh-cookie с `/auth` на `/api/auth`, включая удаление при выходе. Origin запроса со своего фронтенда переводится в Origin upstream; чужие Origin сохраняются для проверки бэкендом. На другом прокси нужны такие же правила. Если HTTPS завершается перед Nginx, настройте проверку Origin под внешний адрес фронтенда или добавьте этот адрес в `ALLOWED_ORIGINS` бэкенда. Для production требуется HTTPS: refresh-cookie бэкенда по умолчанию имеет `Secure`. Для разработки используйте `localhost`. При прямом подключении к API нужны общий сайт для SameSite=Lax cookie, разрешённый Origin и CORS с credentials.

[Swagger бэкенда](http://149.154.68.183/api/docs#/depths/get_depths_depths_get).

В локальном HTTP-прокси Vite для `localhost`, `127.0.0.1` и `::1` у cookie ответов входа, обновления сессии и выхода снимается `Secure`: Safari иначе не сохраняет такую cookie на HTTP localhost. `HttpOnly`, `SameSite`, срок действия и путь сохраняются. Для HTTPS, сетевых адресов и production Nginx это исключение не действует. После обновления старой версии фронта войдите один раз, чтобы сохранить refresh-cookie.
